# 班級作品牆

Padlet 風格的班級作品展示工具。老師可以建立多個班級，學生進入指定班級後提交程式作品連結，頁面會自動顯示縮圖與作品卡片。

## 目前功能

- 建立多個班級入口
- 用資料夾把幾個班級收在一起（例如「五年級 Scratch 動畫」放 501～503），點資料夾可一次看全部班級的作品，上方可切換「全部／單一班級」；資料夾可收合（收合狀態只記在這台電腦）
- 作品卡片縮小，桌機一列約 5 件、手機一列 2 件；卡片標題也是連結，縮圖載不出來時可以直接點標題開作品
- 作品區右上角可切換「卡片／清單」：清單一列一件，依班級、作者排序，標題直接點開作品（手機版只顯示班級、作者、作品）；選擇只記在這台電腦
- 沒登入也沒有班級連結的訪客，會看到各資料夾的封面卡片（班數件數＋4 張縮圖），不能點進去。縮圖盡量來自不同班級：每個有交作品的班級各取最新一件，班級不足 4 個再輪流補各班次新的作品；沒交作品的班級不參與
- **作者去識別化**：卡片與清單的作者一律顯示「501 學生 03」（同一班內依第一次提交的時間編號，同一位學生永遠同一個編號），不顯示姓名與帳號。資料庫裡的 `authorName` 沒動，只是不畫出來
- **老師自己提交的示範作品不列入**：卡片、清單、件數、資料夾封面都排除，只有老師登入時計數旁會提示「另有 N 件老師提交的已隱藏」。老師批次匯入的作品會正常顯示，作者標為「老師匯入」。
- **評審分享連結**：老師在資料夾畫面按「複製評審分享連結」，評審打開就是唯讀的作品清單／卡片，不用登入、沒有送作品表單、只看得到去識別化的編號（見下方〈評審分享連結〉）
- 複製班級專屬連結給學生
- 學生登入後提交作品標題、網址與說明。同一帳號在同一班級提交同一網址只收一次，換標題或說明也會提示已送出。
- 老師可在管理區批次匯入／匯出多班作品 CSV。
- 家長拿到班級連結免登入即可瀏覽作品
- 作品牆自動產生網站縮圖
- 未設定 Firebase 時可用本機示範模式
- 填入 Firebase 設定後可使用 Google 登入與 Firestore 同步

## 多班作品 CSV

1. 教師登入後，開啟「批次匯入／匯出作品」，下載 CSV 範本。
2. 用 Excel 或 Google 試算表填寫「班級」、「作品標題」、「作品網址」及選填的「說明」，另存為 UTF-8 CSV。每列一件作品，可混填自己管理的班級。「班級」可填完整名稱或可唯一對應的三位數班級簡稱。若同名或同簡稱，請填班級代碼，可從單班頁面或匯出檔取得。
3. 選擇檔案後，查看各班的新增件數與略過原因。確認後，系統只新增有效且該班未有相同網址的作品。若匯入中斷，可以繼續，已寫入的作品會略過。
4. 匯出時勾選任意多班，下載一份含班級名稱、班級代碼、標題、網址及說明的 CSV。匯出的是作品牆上顯示的作品，檔案不含學生帳號、姓名或提交時間。匯出檔也可作為匯入檔使用。

如果標題看起來像日期或帶有前導零，例如「1/2」或「007」，用 Excel 的「資料 → 從文字/CSV」開啟並將作品標題欄設為文字。

## Firebase 連線

目前已接到 Firebase 專案 `study-b2e59`：

- Firebase Web App：`study-web`
- Firestore database：`(default)`
- 班級資料路徑：`projectWallClasses/{classId}`
- 作品資料路徑：`projectWallClasses/{classId}/submissions/{submissionId}`
- 資料夾資料路徑：`projectWallFolders/{folderId}`（`name`、`ownerUid`、`createdAt`）；班級文件用選填的 `folderId` 指向所屬資料夾，沒有就是「未分類」
- 教師帳號：`shine@tmail.ilc.edu.tw`

Firestore 不適合由前端在每次新增班級時建立一個全新的 database instance；這個工具採用「每個班級一個獨立文件 + 子集合」的結構。對老師與學生來說，每個班級會有自己的班級連結與作品資料區。

## 啟用或調整 Google 登入與跨裝置同步

1. 到 Firebase 建立專案。
2. 在 Authentication 啟用 Google provider。
3. 建立 Firestore Database。
4. 在 `firebase-config.js` 設定 `window.TeacherProjectWallFirebaseConfig`。GitHub Pages 由部署流程產生這個檔案。
5. Firestore Rules 正本在 repo 根目錄的 `firestore.rules`（整個 `study-b2e59` 專案共用，別在這裡另抄一份）。改完用 `firebase deploy --only firestore:rules` 上線。

## 誰能看、誰能貼

- **看作品**：拿到班級連結（`?class=...`）的人免登入就能看，方便家長瀏覽。
- **列出所有班級**：需要登入，所以沒有連結的人翻不到其他班。
- **貼作品**：學生要用 Google 登入，畫面以去識別化編號顯示作者。
- **刪作品**：只有建立該班的老師。
- **資料夾**：老師才能管理與點進去看；訪客只看得到封面卡片（名稱、班數件數、最新 4 張縮圖），**封面裡沒有班級代碼，所以翻不到班級**。封面由老師端開著頁面時自動重算寫回 `summary` 欄位，老師沒開頁面時會停在上次的樣子；刪資料夾不會刪到裡面的班級與作品，班級會回到「未分類」。

## 評審分享連結

老師（教師帳號登入）點進資料夾，會出現「複製評審分享連結」。連結長這樣：

```
…/班級作品牆/?share=class-xxxx,class-yyyy,…&title=資料夾名稱
```

- 連結裡直接帶各班代碼，所以**不用改 Firestore 規則**，也不會把全部班級代碼公開出去（訪客封面刻意不露班級代碼，這點維持不變）。班級文件與作品本來就是公開可讀，評審的瀏覽器直接讀。
- 評審看到的是唯讀畫面：資料夾名稱、各班篩選、卡片／清單切換；沒有送作品表單、沒有管理與刪除按鈕。
- 只有連結裡有的班級看得到。**資料夾之後新增班級，舊連結不會自動多出來，要重新複製一次。**
- **沒辦法單獨撤銷**：跟班級連結一樣，拿到連結就看得到。真的要收回，只能到 Firebase 主控台刪掉那些班級文件（作品牆畫面目前沒有「刪除班級」功能）。
- 連結裡的班級代碼會先檢查格式（英數、底線、連字號），不合格的直接丟掉。

## 縮圖說明

目前使用 `image.thum.io` 產生公開網站縮圖。若學生提交的網站禁止外部截圖或需要登入，縮圖可能無法顯示，但作品連結仍可開啟。
